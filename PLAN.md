## 2. Что показала проверка сайта

### 2.1. Доступ и ограничения

- Из Германии `mintrans.gov.ru` не отвечает: TCP-таймаут 20 с. Через туннель с российским выходом страница отдаётся за 0,6–1,5 с.
- Отправлено около 200 запросов подряд, 1 запрос в секунду. Ответов 403 и 429 не было.
- Дважды пришёл разовый HTTP 500 на первых запросах. Повтор через секунду дал 200, значит ретраи на 5xx обязательны.
- `/opendata/list.csv` и `/opendata/*/meta.csv` висят до таймаута (60 с). CSV с данными наборов отдаются нормально.
- Ограничения туннеля:
  - он нестабилен, ночью медленный;
  - один ключ рассчитан на одного клиента;
  - нельзя ставить `HTTPS_PROXY` глобально: из РФ недоступен API Anthropic.
- Прокси нужно передавать только HTTP-клиенту парсера через отдельную переменную.

- Сайт работает на October CMS. Весь контент отдаётся в серверном HTML, JS не нужен.
- ID документа в `/documents/{type}/{id}` глобальный, тип в URL сайт игнорирует.
- На карточке документа есть:
  - заголовок `h1`;
  - дата «Опубликовано DD Месяц YYYY»;

- На 73 страницах документов раздела 180 нет ни одной HTML-таблицы. Все данные лежат в файлах.

## 3. Недостатки текущего кода

1. **Охват.** Обходится только раздел 180. Статистические документы, не привязанные к разделу, теряются. Открытые данные, отчёты и бюджетный раздел не охвачены.
2. **Данные не извлекаются.** Парсер собирает только ссылки и скачивает файлы. Таблиц из PDF/DOC/XLS/RAR на выходе нет, а именно это и есть «данные статистики».
3. **Нет поддержки прокси.** Сайт доступен только с российского IP. `requests` без PySocks не умеет SOCKS.
4. **Ретраи.** 5xx (повторять) и 403/429 (остановиться и ждать) не различаются. Пауза линейная, 1–3 с.
5. **Скачивание.** Файл целиком читается в память, таймаут 30 с — на медленном туннеле большие файлы обрываются. Нет докачки (`.part` + `Range`). Resume ищет файл по имени с расширением из подсказки: если расширение потом уточнилось (`bin` → `pdf`), файл скачивается заново.
6. **Неполные метаданные.** Не сохраняются дата публикации, текст карточки, исходное имя файла из `Content-Disposition`, `Last-Modified`/`ETag`.
7. **Ссылки только типа 7.** Регулярка `^/documents/7/\d+$` захардкожена, ссылки вида `/documents/11/...` отбрасываются.
8. **Нет инкрементальности.** JSONL пишется только в конце обхода: падение на 70-м документе теряет всё. Повторный запуск всегда идёт с нуля.
9. **Валидация.**
   - `validate --require-download` ищет файлы в `config.OUTPUTS_DIR`, а не рядом с JSONL;
   - параметр `--files-dir` не используется;
   - пустой `file_size` считается ошибкой, хотя на сайте размер бывает не указан.
10. **Тесты.** Фикстуры синтетические (446 и 693 байта), реальной разметки сайта в тестах нет.
11. **Организация.**
    - результаты и `.venv` лежат внутри пакета;
    - 133 МБ дубликатов в `outputs/bulletin/`;
    - код, который создал `bulletin/`, отсутствует;
    - запуск только через `PYTHONPATH=...`.

## 5. Этапы работ

### Этап 0. Уборка (0,5 дня)

- `git init`, `.gitignore`, первый коммит текущего состояния как точка отсчёта.
- Перенести код в `src/mintrans_stats/`, сделать `pyproject.toml` (uv), CLI `mintrans-stats`.
- Удалить `.venv`, `__pycache__`, `.DS_Store`, `.pytest_cache` из дерева.
- Перенести `outputs/files` в `data/files`. Удалить дубликат `outputs/bulletin/` после сверки sha256.
- `dev/` перенести в `docs/history/`.

### Этап 1. HTTP-слой (0,5–1 день)

- `httpx` + `socksio`. Прокси задаётся только через `MINTRANS_PROXY=socks5h://127.0.0.1:1080`, без глобальных переменных.
- По умолчанию строго последовательно, 1 запрос в секунду. Параллельность настраивается, максимум 2.
- Обработка ответов:
  - 5xx и таймауты: повтор с экспоненциальной паузой, 4 попытки;
  - 403/429: остановка обхода с понятным сообщением;
  - страница «Access to resource was blocked» обрабатывается как блокировка.
- Отдельный короткий таймаут для известных «висящих» URL (`meta.csv`, `list.csv`).
- Кеш сырого HTML на диске. Повторный разбор работает без сети, а снимки страниц становятся фикстурами тестов.
- Команда `mintrans-stats check` проверяет страну выхода и доступность сайта.

### Этап 2. Обнаружение и метаданные (1–1,5 дня)

- Обход раздела 180, параметризованный id раздела, чтобы подключить 181 и другие.
- Поиск по `/documents?q=...` по списку ключевых слов из конфига: «бюллетень», «статистическ», «Транспорт России», «1-контракт», «1-торги», «показател», «индикатор».
- Тип документа в фильтре ссылок не проверяется: ID глобальный.
- Карточка документа:
  - заголовок, дата публикации (ISO), текст описания;
  - вложения: `file_id`, название, размер с сайта, тип;
  - источник обнаружения (раздел или поисковый запрос).
- Открытые данные:
  - реестр со страницы `/opendata/`;
  - паспорт набора из HTML (`meta.csv` висит);
  - все версии `data-*.csv` и `structure-*.csv`.
- Запись каталога построчно, по мере обхода. Повторный запуск пропускает уже разобранное, если не задан `--refresh`.
- Выход: `catalog/documents.jsonl`, `catalog/files.jsonl`, `catalog/datasets.jsonl`, `catalog/runs/<ts>.json`.

### Этап 3. Скачивание (0,5 дня)

- Потоковая запись в `.part`, докачка через `Range`, затем атомарное переименование.
- Сохраняются sha256, размер, `Content-Type`, исходное имя из `Content-Disposition`, `Last-Modified`.
- Тип файла определяется по сигнатуре: `doc`/`xls`/`msg` различаются по OLE-потокам.
- Уже скачанные 93 файла переносятся в `data/files` и сверяются по sha256, чтобы не тянуть 162 МБ через туннель повторно.

### Этап 4. Извлечение, универсальный слой (1,5–2 дня)

- Рекурсивная распаковка rar/zip с перекодировкой имён CP866/CP1251.
- Конвертация `doc`→`docx` и `xls`→`xlsx` через LibreOffice headless. Нужна установка: `brew install --cask libreoffice`. Запасной вариант для `doc` на macOS — `textutil`.
- Таблицы:
  - xlsx/xls: `openpyxl`/`xlrd`, все листы;
  - docx: `python-docx`, все таблицы;
  - pdf: `pdfplumber` с `dedupe_chars()` для сканов ABBYY.
- Каждая таблица сохраняется в `tables/<file_id>/<n>.csv`. В индекс пишется провенанс: документ, файл, вложенный путь в архиве, страница/лист, номер таблицы, заголовок над таблицей.
- Полный текст каждого файла пишется в `extracted/text/` для поиска и контроля.
- Метрика полноты: сколько файлов дали хотя бы одну таблицу. Список файлов без таблиц выдаётся на ручной разбор.

### Этап 5. Нормализованные наборы (2–4 дня, итеративно)

- **Бюллетень «Транспорт России»** (около 55 выпусков за 2011–2025, 4 эпохи вёрстки): длинный формат `period, period_type, indicator, transport_mode, unit, value, yoy_pct, source_file_id, table_ref`.
  - Для каждой эпохи свой разборщик.
  - Сверка итогов: сумма по видам транспорта равна «всего».
  - Перекрёстная сверка кварталов и года.
- **Формы 1-контракт / 1-торги**: таблицы закупок по периодам.
- **Целевые индикаторы госпрограмм и бюджет**: из файлов раздела 180 и наборов opendata (`statinfo`, `pokazatelitransportprogramm*`, `transportbudget*`, `resulttransportprogramm`).
- **Открытые данные**: перекодировка в UTF-8, объединение версий набора с колонкой `version_date`.
- Выход: `datasets/<name>.csv` и `.parquet`, у каждого описание схемы в `docs/data-model.md`.

### Этап 6. Качество и документация (1 день)

- Тесты на реальных фикстурах:
  - разбор списка, карточки, пагинации, opendata;
  - определение типа файла, распаковка архивов с кириллицей;
  - извлечение таблиц из образцов каждого формата;
  - разбор бюллетеня каждой эпохи.
- Сетевые тесты помечены `@pytest.mark.network` и в CI не запускаются.
- CI: `ruff check`, `ruff format --check`, `pytest -m "not network"`.
- `README.md`: установка, настройка прокси, полный цикл `crawl → download → extract → validate`.
- `docs/site-structure.md`, `docs/data-model.md`, `docs/operations.md`.

## 6. Критерии приёмки

- `mintrans-stats crawl` находит не меньше 75 статистических документов: 73 из раздела 180 и найденные поиском. Сюда входят 93+ файла и 36 наборов открытых данных.
- Повторный запуск без изменений на сайте даёт тот же набор `document_id`/`file_id` и не скачивает файлы заново.
- У каждого файла есть sha256, исходное имя, размер и дата скачивания. Скачивание переживает обрыв туннеля.
- Из каждого файла с табличными данными извлечены таблицы с провенансом. Файлы без таблиц перечислены в отчёте.
- Нормализованный ряд бюллетеня покрывает все выпуски 2011–2025 и проходит сверку итогов.
- `pytest` проходит офлайн. README позволяет запустить полный цикл с нуля.

## 7. Риски

- **Туннель.** Он медленный и нестабильный, один ключ рассчитан на одного клиента: при параллельной работе других клиентов соединения рвутся. Долгие запуски лучше делать днём, с докачкой, либо на российском VPS.
- **Вёрстка бюллетеней.** Она менялась (doc 2011–2016 → docx → pdf 2022+). Специализированный разбор потребует итераций по эпохам.
- **Сканы ABBYY.** Удвоение символов в PDF лечится `dedupe_chars`, но таблицы в сканах могут потребовать ручных правок.
- **Публикации остановились.** После декабря 2025 новых бюллетеней на сайте нет. Если публикация переехала (например, на transport.gov.ru), понадобится отдельный источник.
