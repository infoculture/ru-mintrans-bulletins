# Эксплуатация: доступ к сайту и ограничения

## Российский IP

mintrans.gov.ru не принимает соединения с зарубежных адресов: TCP-соединение висит до
таймаута. Нужен выход в интернет через Россию. Прокси передаётся только HTTP-клиенту парсера
(`MINTRANS_PROXY` или `--proxy`). Клиент создаётся с `trust_env=False`, поэтому глобальные
`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` на него не влияют.

Глобально заворачивать трафик машины в Россию нельзя: из РФ недоступны многие зарубежные
сервисы, в том числе API Anthropic.

Варианты:

1. **SOCKS5-прокси с российским выходом.** Парсер читает адрес из `MINTRANS_PROXY`, httpx
   поддерживает схемы `socks5://`, `socks5h://` и `http://`. В этой работе использовался
   локальный контейнер с туннелем AmneziaWG в московский ЦОД и SOCKS5 на `127.0.0.1:1080`;
   маршруты самой машины при этом не меняются.

   ```bash
   curl -sS --max-time 20 -x socks5h://127.0.0.1:1080 https://ipinfo.io/country   # RU
   export MINTRANS_PROXY=socks5h://127.0.0.1:1080
   uv run mintrans-stats check
   ```

   Особенности такого туннеля:
   - один ключ рассчитан на одного клиента: если тот же конфиг одновременно используется в
     другом месте, соединения рвутся;
   - туннель бывает нестабилен: `General SOCKS server failure`, таймауты и обрывы, ночью
     скорость сильно падает. Клиент делает 4 попытки, после чего команда завершается с
     ошибкой; повторный запуск берёт карточки из кеша и скачанные файлы с диска;
   - схема `socks5h://` обязательна: DNS тоже разрешается через туннель.

2. **Запуск на сервере в России.** Прокси не нужен: склонируйте репозиторий, выполните
   `make venv collect` и перенесите `data/files/` и `data/catalog/` обратно. Долгие обходы
   удобнее запускать там же: ноутбук на батарее уходит в сон, и запросы встают.
   - Запускайте в фоне (`nohup … &`), чтобы обрыв SSH не прервал работу.
   - Не повторяйте в цикле команды, которые что-то запускают: если сессия оборвётся уже
     после старта, повтор запустит второй экземпляр.
   - Проверять, идёт ли процесс, удобнее через `ps -eo pid,args | grep "[m]intrans-stats"`:
     `pgrep -f` находит и саму SSH-команду с этой строкой.

Ключи и конфигурации VPN в репозиторий не кладутся.

## Ограничения сайта

Наблюдения 03.11.2026, около 300 запросов через туннель:

| Наблюдение | Как учтено в клиенте |
|---|---|
| При 1 запросе в секунду ответов 403/429 не было | `delay_s=1.0` по умолчанию, запросы строго последовательные |
| Разовые HTTP 500, повтор через секунду проходит | 5xx, таймауты и обрывы повторяются до 4 раз, пауза 2, 4, 8 с плюс случайная добавка |
| `Range` для `/file/{id}` игнорируется, сервер отдаёт 200 | при обрыве файл качается заново; `.part` перезаписывается |
| `Content-Disposition` содержит исходное имя файла (`pril_3.xls`) | сохраняется в `original_filename` |
| Страница WAF «Access to resource was blocked» (по заметкам первой версии) | `BlockedError`, работа останавливается |

Ответы 403/429 и страница блокировки останавливают `crawl` и `download` (`BlockedError`).
Обходить блокировку сменой IP или увеличением числа потоков нельзя. Нужно выждать и
снизить частоту (`--delay 3`).

## Кеш страниц

Копии HTML сохраняются в `data/raw/html/<хост>/<путь>[__<query>].html`:

- списки разделов при каждом `crawl` запрашиваются заново;
- карточки документов берутся из кеша.

Поэтому повторный обход стоит около 10 запросов вместо 82, а после обрыва обход быстро
доходит до места остановки. `crawl --refresh` перекачивает и карточки. `--no-cache`
отключает кеш полностью.

  «Транспорт России».

- `download --fill-meta` для 54 уже скачанных файлов: 54 запроса заголовков, около минуты.
  У всех файлов есть исходное имя из `Content-Disposition`. `Last-Modified` сайт не присылает.
- `extract` с нуля (конвертация 32 doc через LibreOffice): несколько минут. Повторный запуск
  берёт неизменившиеся файлы из индексов.
- `normalize` и `build-db` работают без сети, около 10 секунд вместе. База
  `data/bulletin.duckdb` занимает около 8 МБ.
