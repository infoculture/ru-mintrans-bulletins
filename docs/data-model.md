# Модель данных

Все файлы лежат в `data/`. В git хранятся исходные файлы выпусков (`data/files/`), каталог
(`documents.jsonl`, `files.jsonl`, `downloads.jsonl`) и Parquet-выгрузка базы
(`data/parquet/`); остальное пересобирается командами `extract`, `normalize`, `build-db`
(`make build`). JSONL — одна JSON-запись на строку, кодировка UTF-8.
Даты в формате ISO `YYYY-MM-DD`, время — UTC `YYYY-MM-DDTHH:MM:SSZ`.

Цепочка: `crawl` → `catalog/documents.jsonl`, `files.jsonl` → `download` → `files/`,
`catalog/downloads.jsonl` → `extract` → `tables/`, `extracted/`, `catalog/extracted.jsonl`,
`tables.jsonl` → `normalize` → `datasets/bulletin_*.csv` → `build-db` → `bulletin.duckdb` и
`parquet/*.parquet` (см. [database.md](database.md)).

## catalog/documents.jsonl

Пишет `crawl`. Одна запись на выпуск бюллетеня, по убыванию `document_id`. Выпуск
узнаётся по словам «информационно-статистический бюллетень» в названии
([classify.py](../src/mintrans_stats/classify.py)). Остальные документы раздела и выдачи
поиска в каталог не попадают, только считаются в сводке запуска.

| Поле | Тип | Описание |
|---|---|---|
| `document_id` | string | глобальный ID документа на сайте |
| `document_url` | string | `https://mintrans.gov.ru/documents/{type}/{id}` |
| `type_id` | string | тип из URL (7 — информационные и аналитические материалы) |
| `title` | string | заголовок карточки (`h1`) |
| `published_at` | date \| null | «Опубликовано …» на карточке |
| `listed_date` | date \| null | дата в списке раздела или в выдаче поиска |
| `description` | string | текст карточки (`.text-block`), обычно пустой |
| `sources` | list | где найден: `{"kind": "section", "section_id": 180}`, `{"kind": "search", "query": "…"}` |
| `files_count` | int \| null | число вложений; `null`, если карточку не удалось получить |
| `crawled_at` | datetime \| null | когда разобрана карточка |

## catalog/files.jsonl

Пишет `crawl`. Одна запись на каждое вложение выпуска. Это вход для `download`.

| Поле | Описание |
|---|---|
| `document_id`, `document_title`, `document_url`, `published_at`, `listed_date` | из выпуска |
| `file_id` | ID файла на сайте |
| `file_title` | название вложения без размера; если на сайте ссылка без текста — название выпуска |
| `file_title_from_document` | `true`, если `file_title` взят из названия выпуска |
| `file_url` | `https://mintrans.gov.ru/file/{id}` |
| `file_type` | тип по CSS-классу на сайте (`pdf`, `doc`, `rar`, …) |
| `file_size` | размер как на сайте (`2493 kb`); может быть пустым |

## catalog/downloads.jsonl

Пишет `download`. Это манифест скачанных файлов: строки `files.jsonl` для успешно
скачанных файлов, к которым добавлены поля:

| Поле | Описание |
|---|---|
| `local_path` | путь относительно `data/`: `files/{document_id}/{file_id}.{ext}` |
| `detected_type` | тип по содержимому файла; он же расширение в `local_path` |
| `sha256` | хеш содержимого |
| `saved_file_size_bytes` | размер на диске |
| `original_filename` | имя из `Content-Disposition` |
| `content_type`, `last_modified` | заголовки ответа сервера (`Last-Modified` сайт не присылает) |
| `downloaded_at` | когда файл скачан |
| `verified_at` | когда файл последний раз проверен этим запуском |
| `previous_sha256` | прежний хеш, если файл скачан заново и изменился |

Манифест переписывается при каждом запуске. Сведения о файлах, которые не перекачивались,
переносятся из прошлого манифеста, если хеш совпал: `original_filename`, `content_type`,
`last_modified`, `downloaded_at`. Строки прошлого манифеста, не попавшие во вход (например,
при `--limit`), сохраняются.

Тип файла определяется по содержимому ([filetypes.py](../src/mintrans_stats/filetypes.py)):
- сигнатуры PDF, RAR, 7z, RTF;
- оглавление ZIP: docx и другие форматы Office;
- потоки в корне OLE-контейнера: `WordDocument` → doc.

Встроенные объекты не сбивают определение. В 29 выпусках в .doc есть встроенные книги
Excel (диаграммы), но они лежат во вложенных хранилищах. Если сервер вернул HTML-страницу
вместо файла, это ошибка: файл не сохраняется.

На 03.11.2026 скачано 54 файла 53 выпусков: 29 doc, 17 pdf, 5 docx, 3 rar (внутри doc).

## catalog/extracted.jsonl

Пишет `extract`. Одна запись на каждый «элемент» — скачанный файл, а у архива — каждый файл
внутри него.

| Поле | Описание |
|---|---|
| `item_id` | `{document_id}/{file_id}`; член архива — `{document_id}/{file_id}#{n}` |
| `document_id`, `file_id` | источник |
| `local_path`, `source_sha256` | исходный файл и его хеш |
| `member` | путь внутри архива; у вложенного архива — через `!`: `a.zip!b/c.doc` |
| `kind` | тип по содержимому: `pdf`, `doc`, `docx`, … |
| `converted_path` | docx, полученный из doc/rtf через LibreOffice |
| `status` | `ok` — есть таблицы; `no_tables` — только текст; `unsupported` — формат не читается; `error` |
| `error` | текст ошибки |
| `tables` | число таблиц |
| `text_path`, `text_chars` | полный текст (`extracted/text/{слаг}.txt`) и его длина |
| `needs_ocr` | PDF без текстового слоя — таблицы и текст только через распознавание |
| `extracted_at` | время обработки |

Номера членов архива `#n` идут по отсортированным путям и не меняются, пока не изменился
архив: состав распакованного архива хранится в `extracted/archives/{слаг}/.members.json`.

## catalog/tables.jsonl

Пишет `extract`. Одна запись на таблицу (2143 таблицы на 03.11.2026). Таблицы сохраняются
как есть: многоуровневые шапки, объединённые ячейки и единицы измерения остаются как в
источнике.

| Поле | Описание |
|---|---|
| `table_id` | `{item_id}:t{NNN}` |
| `item_id`, `document_id`, `file_id`, `member` | источник |
| `location` | `page N` (PDF) или `body` (Word) |
| `caption` | текст перед таблицей: заголовок и строка единиц (Word), строки над таблицей (PDF) |
| `n_rows`, `n_cols` | размер |
| `csv_path` | `tables/{слаг}/t{NNN}.csv` — UTF-8, разделитель запятая |

Как читаются форматы:
- PDF — pdfplumber с `dedupe_chars()`: сканы ABBYY дублируют символы;
- doc и rtf — конвертация в docx через LibreOffice;
- docx — разбор `word/document.xml` (`gridSpan` → пустые ячейки справа, продолжение
  `vMerge` → пустая ячейка).

Пустые крайние строки и столбцы обрезаются. Одностолбцовые «таблицы» в PDF (рамки вокруг
абзацев) отбрасываются.

## datasets/ — нормализованные наборы

Пишет `normalize`. Все файлы — CSV в UTF-8 с разделителем-запятой и строкой заголовков. Те же
данные с типами и описаниями — в базе DuckDB ([database.md](database.md)).

### bulletin_values.csv

Каждая числовая ячейка каждой таблицы всех выпусков бюллетеня «Транспорт России»
(около 95 тыс. строк). Строки номеров граф («1, 2, 3 …») к данным не относятся и пропускаются.

| Поле | Описание |
|---|---|
| `document_id`, `report_period`, `report_year`, `report_month_to` | выпуск и его период: `2025-01..09` — январь–сентябрь 2025 |
| `table_id`, `location`, `caption` | таблица (см. `tables.jsonl`) и её подпись |
| `topic` | ключевой показатель, если таблица сводная по видам транспорта: `passengers_carried`, `passenger_turnover`, `freight_carried`, `freight_turnover` |
| `unit` | единица по подписи (`млн т`, `млрд т-км`, `млн чел.`, `млрд пасс.-км`, `тыс. т`) или `%` для процентных столбцов |
| `row_index`, `row_label`, `row_note` | строка: подпись без сносок и сама сноска |
| `mode` | вид транспорта по подписи строки (см. ниже) или пусто |
| `col_index`, `col_header` | столбец и его шапка (уровни шапки через ` / `) |
| `col_period`, `col_year`, `col_month_from`, `col_month_to` | период столбца из шапки |
| `measure` | `value` или `percent` (столбец «в % к …») |
| `value`, `value_raw`, `value_note` | число, исходный текст ячейки, сноска при числе |

### bulletin_core.csv и bulletin_core_series.csv

Ключевые показатели из сводных таблиц «по видам транспорта» и «транспорта общего
пользования».
- `bulletin_core.csv` — все наблюдения из всех выпусков. Один период обычно встречается
  дважды: как текущий в своём выпуске и как прошлогодний в следующем.
- `bulletin_core_series.csv` — ряд без повторов. Для каждого (показатель, вид, период) берётся
  значение из самого позднего выпуска, то есть последний пересмотр. Значения с меткой
  `unit_suspect` уступают значениям без метки.

Поля: `indicator`, `mode`, `period`, `year`, `month_from`, `month_to`, `value`, `unit`,
`row_label`, `document_id`, `report_period`, `table_id`, `flags`.

Виды транспорта (`mode`):

| `mode` | Подписи в выпусках |
|---|---|
| `total` | «Транспорт – всего» (2021+), «Транспорт всех отраслей экономики» |
| `total_mintrans` | «Транспорт отраслей Минтранса России» |
| `rail`, `rail_industrial` | железнодорожный (общего пользования), промышленный железнодорожный |
| `road`, `bus` | автомобильный; автомобильный (автобусный) |
| `air`, `sea`, `inland_water`, `water` | воздушный, морской, внутренний водный, водный (2011–2012: морской и речной вместе) |
| `tram`, `trolleybus`, `metro`, `urban_electric` | городской электрический транспорт |
| `pipeline` | трубопроводный |

Подвиды («из него внутренние перевозки», «пригородные») в ключевые ряды не входят: они есть в
`bulletin_values.csv` без `mode`.

Охват итогов менялся. До 2021 года пассажирские таблицы давали только итог по отраслям
Минтранса (`total_mintrans`), с 2021 года — «Транспорт – всего» (`total`). Под одной подписью в
разных выпусках бывает разный состав: пересмотр годового итога за 2022 год различается между
выпусками на десятки процентов. Ряды с разным охватом не склеиваются автоматически, для анализа
смотрите `bulletin_checks.csv`.

### bulletin_checks.csv

| `check` | Что проверяет | `ok = False` значит |
|---|---|---|
| `total_vs_sum` | итог против суммы видов в той же таблице (для `total_mintrans` и `total`; промышленный ж/д транспорт пробуется в обеих группах) | расхождение больше 1% |
| `revision` | одно и то же значение (показатель, вид, период) в разных выпусках | пересмотр больше 1% |
| `unit_suspect` | то же, но значения различаются в 100 раз и больше | вероятна другая единица (тыс. т вместо млн т) |

Результат на 03.11.2026:
- `total_vs_sum`: сошлись 639 из 640. Единственное расхождение — ошибка в самом выпуске:
  пассажирооборот за I квартал 2019 года, 116,4 против итога 111,4.
- `unit_suspect`: два случая — воздушные грузы за I полугодие 2023 и 2024 годов, 211 и
  218,4 «млн т» вместо 0,211 и 0,218.

## catalog/runs/

Сводки запусков: `crawl-*.json`, `download-*.json`, `extract-*.json`, `normalize-bulletin-*.json`,
`build-db-*.json`. В сводке есть:
- счётчики по источникам;
- выпуски, найденные вне раздела;
- типы файлов;
- ошибки и число HTTP-запросов.
